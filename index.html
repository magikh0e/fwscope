Drop firewall or WAF logs here

Firewalls: UFW, nftables / iptables / firewalld, OPNsense / pfSense, Windows Firewall, plus fail2ban's log and Suricata IDS alerts. Web application firewalls: ModSecurity, Coraza and Cloudflare firewall events.

Windows: pfirewall.log (copy it out from an admin prompt first).

ModSecurity: the audit log (modsec_audit.log, JSON or native format) or the ModSecurity: lines in an Apache or nginx error log.

OPNsense / pfSense: /var/log/filter/filter_*.log, remote-syslog copies, or Live View API JSON.

Plain ufw.log, rotated .gz files, kern.log/syslog, dmesg -T or journalctl output (text or -o json).

Drop several at once, or a whole folder, to merge them. Add more later with Add logs or by dropping them on the dashboard. Duplicates across files are skipped (UFW writes the same line to ufw.log, kern.log and syslog).

For a world map and network owners, drop a GeoIP database too (.mmdb or .mmdb.gz).

Blocklists: drop a plain list of addresses and ranges (Spamhaus DROP, FireHOL .netset, your own) to mark sources on it. Checked here, never looked up online.

OPNsense / pfSense: drop a config backup (config-*.xml) and/or rule_ids.json to show interface and rule names.

Everything is parsed in this browser tab. Nothing is uploaded anywhere, unless you turn on the optional hostname lookups.

Grab the logs

UFW / iptables

sudo cp /var/log/ufw.log* ~/ && sudo chown $USER ~/ufw.log*
journalctl -k -g 'UFW ' -o short-iso --since '-7d' > ufw-journal.log
journalctl -k -g 'UFW ' -o json > ufw.json
scp you@server:'~/ufw.log*' .

nftables / iptables / firewalld

journalctl -k -g 'SRC=' -o short-iso --since '-7d' > netfilter.log
  • Any kernel log line with SRC=, DST= and PROTO= works. Its log prefix becomes the action: nft-drop:, FINAL_REJECT:, IPTables-Dropped:.
  • Prefixes that say drop, reject, deny or block count as blocks; accept, allow or pass as allowed; anything else as logged.
  • firewalld: firewall-cmd --set-log-denied=all turns logging of refused packets on.

fail2ban

sudo cp /var/log/fail2ban.log* ~/ && sudo chown $USER ~/fail2ban.log*
  • Ban, Unban and Found lines; the jail shows as the rule. Load it with the web or firewall logs to see who fail2ban caught.

Suricata (IDS / IPS)

scp 'root@opnsense:/var/log/suricata/eve.json*' .
  • Alerts from eve.json (other event types are skipped) or fast.log. The signature shows as the rule; seen:ids filters to sources Suricata alerted on.

OPNsense / pfSense

scp 'root@opnsense:/var/log/filter/filter_*.log' .
ssh root@opnsense 'cat /var/log/filter/latest.log' > opnsense-today.log
  • Web UI: Firewall → Log Files → Plain View, then the download icon at the top right of the table.
  • SSH is off by default: System → Settings → Administration → Secure Shell.
  • One file per day; a busy firewall writes a few hundred MB a day. Drop a day or two at a time, or gzip them first (gzip filter_*.log).
  • Logs sent to a remote syslog server work too.

Windows Firewall

Set-NetFirewallProfile -All -LogBlocked True -LogMaxSizeKilobytes 32767
Copy-Item C:\Windows\System32\LogFiles\Firewall\pfirewall.log* $HOME\Desktop\
  • Run both in an admin PowerShell. Logging is off by default; the first line turns on logging of dropped packets.
  • Rename each copy after its PC (office-pc.log): the log has no hostname, so the file name is used.

For program names, export the Security log's firewall events instead (needs auditing on, first line):

auditpol /set /subcategory:"Filtering Platform Connection" /success:enable /failure:enable
Get-WinEvent -FilterHashtable @{LogName='Security';Id=5152,5156,5157} -MaxEvents 200000 | % { $x=[xml]$_.ToXml(); $d=[ordered]@{EventID=$_.Id;TimeCreated=$_.TimeCreated.ToUniversalTime().ToString('o');Computer=$_.MachineName}; $x.Event.EventData.Data | % { $d[$_.Name]=$_.'#text' }; $d | ConvertTo-Json -Compress } | Set-Content -Encoding utf8 "$HOME\Desktop\$env:COMPUTERNAME-wfp.json"

ModSecurity / Coraza

scp 'you@web:/var/log/modsec_audit.log*' .
grep 'ModSecurity:' /var/log/nginx/error.log > modsec-errors.log
  • The audit log path is set by SecAuditLog. The JSON format (SecAuditLogFormat JSON) and the default native format both work.
  • Apache and nginx error logs work too: each request's ModSecurity: lines are grouped by their unique_id.
  • Name a file after its server (shop-web.log) to tell servers apart.

Cloudflare

Security events from the GraphQL API, with an API token that can read Analytics (set your zone ID and start time):

curl -s https://api.cloudflare.com/client/v4/graphql -H "Authorization: Bearer $CF_API_TOKEN" -d '{"query":"{viewer{zones(filter:{zoneTag:\"ZONE_ID\"}){firewallEventsAdaptive(limit:10000,orderBy:[datetime_ASC],filter:{datetime_gt:\"2026-11-01T00:00:00Z\"}){action source ruleId description clientIP clientRequestHTTPHost clientRequestHTTPMethodName clientRequestPath clientRequestQuery userAgent edgeResponseStatus datetime rayName}}}}"}' > cf-events.json
  • Or a Logpush job for the firewall_events dataset (one JSON object per line).
  • Blocks, challenges, logged and skipped events show as WAF BLOCK, WAF CHALLENGE, WAF DETECT and WAF ALLOW, grouped by the Cloudflare product that acted.
  • How far back the API goes depends on your plan; it returns at most 10,000 events per query.

What gets logged

UFW

  • sudo ufw logging low: blocked packets that hit the default policy, plus rate-limited (LIMIT) ones.
  • medium: adds allowed new connections (ALLOW) and invalid packets.
  • high / full: adds AUDIT and less rate limiting. Noisy.
  • Per-rule logging: ufw allow log 22/tcp or ufw deny log-all ...

OPNsense

  • Each rule logs only if its Log box is ticked (Firewall → Rules → edit the rule).
  • The built-in default block and pass rules have their own logging switches under Firewall → Settings.
  • Rules and interfaces show up as IDs (vtnet0, rule 439d8dff…). To see names, drop these along with the logs:
    • a config backup (System → Configuration → Backups → Download): your own rules, plus interface names like LAN and WAN
    • for built-in rules (default deny, bogons ...): open https://<firewall>/api/diagnostics/firewall/list_rule_ids while logged in and save the page as rule_ids.json
    Only the names are kept, in this browser. The rest of the backup, including its passwords and keys, isn't stored.

Windows Firewall

  • -LogBlocked True: dropped packets (DROP). -LogAllowed True adds allowed connections (ALLOW), which is very noisy on a desktop.
  • No interface, rule or TTL is logged. Direction shows as receive (In) or send (Out).
  • Times are local with no timezone, so read the log in the same timezone as the PC.

ModSecurity

  • SecAuditEngine RelevantOnly (the usual setting) logs requests that tripped a rule. Each one shows as WAF BLOCK if it was stopped, or WAF DETECT if it was only flagged.
  • Attack types (SQLi, XSS, LFI, RCE ...) come from the OWASP Core Rule Set's rule numbers, or from attack-* tags for other rule sets.
  • Load firewall logs alongside and addresses seen by both are marked firewall + WAF; filter them with seen:both. With a fail2ban log loaded, seen:f2b shows the sources it banned.

Where sources come from

Add an IP-to-country and/or IP-to-network (ASN) database in .mmdb format to see this map. Drop it on the page or use the button. It's kept in this browser for next time, and every lookup happens locally.
  • DB-IP Lite: grab "IP to Country Lite" and "IP to ASN Lite" (MMDB). Free, no account, CC BY 4.0, updated monthly. The .mmdb.gz works as downloaded.
  • IPinfo Lite: country and ASN in one file, free with a sign-up.
  • MaxMind GeoLite2 Country / ASN: free account and license key.

If blocking were on

CRS blocks a request once its inbound anomaly score reaches the threshold (5 by default), and a response once its outbound score reaches the outbound threshold. Pick a threshold to see what it would catch. "Possibly legitimate" means your own or LAN addresses, sources that mostly send a known crawler's user agent, or requests that tripped only protocol-policy rules and no attack rules.

Tuning suggestions

Rules that fire mostly on possibly legitimate traffic (verified crawlers, your own or LAN addresses) for one path or group of addresses. "Unblocks" is what excluding that rule there would change at the threshold picked above: possibly legitimate requests that would get through, and other requests (likely attacks) that would too. Block suggestions

Based on your WAF logs: sources the WAF caught attacking (web scans, web hammering, attack rules, fake crawlers) whose requests still reached the web app, as they do in detection-only mode. Firewall logs, if loaded, only add supporting evidence (a port scan, "firewall + WAF"); traffic your firewall already drops isn't a reason to block anything. Never suggested: your own and LAN addresses, Cloudflare's ranges, verified crawlers, and your never-block list. Three or more strong attackers in one /24 (IPv6 /64) are also offered as the whole range. Tick what to block, then write a script; nothing is applied from here.
